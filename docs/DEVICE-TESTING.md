# Release device checks

Automated checks use isolated app data, simulated provider responses and synthetic microphone audio. They do not establish physical microphone accuracy, biometric behavior or real network reliability. The app's Performance page has a manual checklist; a checked item records only the owner's confirmation on that PC.

Before a stable release, record the app version, Windows build, display scaling, microphone model and Android version used for these checks:

- Select an actual microphone in Voice. Run the six-second test in Windows speech and each downloaded engine you intend to support. Check Bluetooth reconnect, hardware mute, unplugged input, denied Windows microphone permission and exclusive-use errors. For OpenAI, verify the recorded sample is sent only after the explicit test action and the saved key is used.
- Try chat dictation, global hold-to-talk, assistant replies and meeting capture with the same microphone and language. The optional Windows keyword listener uses the Windows default input. Speak-a-reply and the utterance after the keyword use the shared setup. Ensure recording indicators stay visible and cancel releases the microphone.
- Move Nook between monitors at 100%, 125%, 150% and 200% Windows scaling, including a monitor above or to the left of the primary screen. Exercise text enlargement, webview zoom, reduced motion, hidden/pinned notch modes, dialogs, overlays and monitor disconnect/reconnect. Check that controls remain reachable without resizing a hidden native window.
- Navigate settings, the preview editor, model choices, meeting search, task review and window-context preview with keyboard only. Test with Windows Narrator, especially labels, active recording announcements, focus restoration and pending-request interruptions. Crop and redaction also have numeric rectangle controls for keyboard users.
- Lock and unlock, suspend and resume while recording, downloading a model, transcribing, playing a spoken response, and waiting for a phone reply. Confirm audio is stopped on lock and pending actions cannot execute after expiry or revocation.
- Test an Android phone on the same LAN, an address change, a guest network, revoked pairing, certificate change, expired token and an optional configured remote relay. Verify fingerprint/passcode approval against the exact current request. Check widgets after midnight, loss of connection and background-job deferral. Do not mark these tested based solely on a desktop simulation.
- Install a previous release in a disposable Windows account or VM and upgrade. Interrupt an update download, reconnect and retry. Confirm settings and credentials survive; invalid or incomplete payloads must not install. Verify uninstall choices and the installer publisher. Current releases remain unsigned unless the owner configures signing separately.

Run `npm test`, `npm run smoke:notch`, `npm run smoke:refinements`, `npm run smoke:polish`, `npm run pack`, and `npm run smoke:packaged` before release. The notch check covers hover re-entry, stable widgets during background updates, pointer clicks across updates, draft focus, and settled window bounds. The refinement smoke test writes layout, context-review, voice and meeting results plus screenshots to `dist/refinements-qa/`. Android source must also pass its build/lint workflow and physical-device checks. The CI workflow verifies desktop test results and retains visual artifacts for review; it does not mark device tests complete or publish a release.

Check both wake engines separately. For Parakeet, select a real microphone, test your chosen phrase and spoken language, pause between the phrase and command, and verify unrelated speech never becomes a chat draft. Check the twenty-second command window, physical mute/unplug, lock/sleep cancellation and CPU usage during background noise. The automated suite uses a synthetic microphone and mocked recognition; it does not establish real Parakeet accuracy. Practice right modifiers with your keyboard layout, especially AltGr and app-specific shortcuts. Verify Stable/Beta transitions and recovery in a disposable account before distributing a beta. Signed installer testing needs an owner-provided certificate and real upgrade validation.


For the personal-workspace additions, run `npm run smoke:expansion` and `npm run smoke:refined`. Check speech interruption with real Windows and ElevenLabs playback, including generation failures, mute/quiet hours, lock/sleep and cancellation before a queued sentence starts. The automated checks use simulated speech and do not validate live ElevenLabs billing or actual microphone behavior. Test permitted memory against a provider that is allowed, one that is denied, disabled memory and a connection probe; changes affect future requests only. Verify Coinbase view-only keys on a real account and refuse trade/transfer keys before balances, then compare available plus held funds against Coinbase. Test real Base/Arbitrum native and explicitly entered token contracts; RPC availability, prices, rounding and unsupported assets need real-account review. Do not infer financial accuracy from fixture responses. For each supported scaling and theme, check all costume previews, collection import review, keyboard queue browsing and the responsiveness report. Normal builds remain unsigned; the signed workflow requires the owner's certificate and publisher verification.

For project tools, run `npm run smoke:hub`. Its isolated checks cover General/project chat restoration, memory scope, reviewed routines, local reminder delivery/snooze, draft-only shelf attachments, unified search and layered outfits. Also check these on a real desktop:

- Schedule reminders across quiet hours, a weekend, daylight-saving transitions, Windows time-zone changes, sleep and restart. Check the displayed local clock and single overdue alert. Windows notifications may be disabled independently of Nook; confirm notch reminders remain actionable. Nook does not wake a shut-down PC.
- Create two spaces with different chats, source links, memories and models. Confirm a project switch is blocked while recording, replying or awaiting an approval. Check the confirmation, cleared draft attachments and assistant context, retention expiry, switching back to General and reopening after restart. Saving spaces does not enable conversation saving.
- Run a reviewed app/profile/timer routine with real approved apps, then revoke an app, remove a profile, cancel mid-run and lock the screen. Verify only reviewed steps run and later steps stop. Completed launches/profile changes are not undone.
- Create grouped completion events with multiple source projects. Check quiet digest, muted agents, disabled event kinds, group snooze/resume and quiet hours. Approval requests must stay separate and require their existing confirmation.
- Drop text and image files into both shelves. Preview, pin, unpin, restart, expire, attach a draft and clear the shelf. Verify originals remain untouched, temporary snapshots do not survive restart, and only pinned snapshots are saved encrypted. Check keyboard navigation and focus after closing dialogs.
- Try layered hats, glasses/headphones and clothing with all skins, light/dark themes, 100–200% display scaling and reduced motion. Scrub each new performance in the animation studio; verify hidden previews stop rendering and the new notch panels remain scrollable and clickable during updates.
- Trigger a microphone failure and a provider failure. Confirm recovery links open the right settings and the reviewed export contains only the displayed redacted fields. Do not infer successful real microphone recognition or native notification delivery from fixture results.
